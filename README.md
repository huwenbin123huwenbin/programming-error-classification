# Where the Metadata Ends: Verdict Classification from Submission Logs

**Paper**: Where the Metadata Ends: Observational Equivalence and the Limits of Verdict Classification from Submission Logs

**Author**: Wenbin Hu (School of Computer Science, Xijing University)

**Journal**: ACM Transactions on Computing Education (TOCE) — under review

---

## Overview

This repository contains the data and the full analysis pipeline for a study
that asks how much verdict information a programming-judge submission log
carries when the source code is not available.

The central result is not a model ranking but an identifiability analysis.
1,504 of the 13,360 submissions (11.3%) report **0 ms, 0 KB and 0 tests passed**
while spanning three verdicts — a compilation error, an early crash and a wrong
answer on the first test all leave the same trace. No classifier given these
fields can separate them; this bounds Compilation Error at F1 ≈ 0.77 and
explains most of the Wrong Answer ↔ Runtime Error residual.

### Key results (test partition, n = 2,672)

| Model | Test Acc | 95% CI | Macro F1 | Cost / 1k |
|---|---|---|---|---|
| Random Forest (6 fields) | 91.80% | [90.8, 92.8] | 0.798 | <$10⁻⁶ |
| **Gradient Boosting (6 fields)** | **91.77%** | [90.6, 92.8] | **0.799** | <$10⁻⁶ |
| Logistic Regression (6 fields) | 85.63% | [84.2, 86.9] | 0.494 | <$10⁻⁶ |
| DeepSeek-V3, three-shot (5 fields), valid outputs | 76.65% | [75.0, 78.2] | 0.545 | $0.01 |
| Qwen2.5:3B, three-shot (5 fields), valid outputs | 35.50% | [33.6, 37.4] | 0.231 | $0.00 |
| Majority-class rule (always WA) | 76.61% | — | — | — |

Supervised cost is priced from measured single-core inference (RF about 12–23 ms,
GB about 5–11 ms, LR about 0.2 ms per 1,000; ranges span repeated runs of
`latency_benchmark.py` under varying host load; at most ≈$3×10⁻⁷ at
$0.04 per vCPU-hour); DeepSeek-V3 at standard list pricing (≈215 input +
≈22 output tokens per eight-item call), half that at the promotional rate
in effect during data collection.

Per-class F1 (Gradient Boosting): TLE 0.99, MLE 0.95, WA 0.95, CE 0.77, RE 0.33.
A submitter-disjoint replication gives 93.13% with no rank change.

**Dataset**: 13,360 failing Codeforces submissions from 4,005 programmers
(WA 10,234 · TLE 1,288 · CE 980 · RE 656 · MLE 202), split 10,688 / 2,672.

**Fields** (all present in the public submission payload):
`problem_rating`, `time_consumed_ms`, `memory_kb`, `language_encoded`,
`passed_test_count`, `problem_type` (the lettered slot of the problem within
its contest).

Two candidate fields are deliberately excluded and the reasons are documented
in the paper: `hour` cannot be constructed because the payload carries no
timestamp, and a submitter-history aggregate adds no gain that survives
correction (a nominal +0.67 pp when computed from earlier training
submissions only, exactly zero once submitters are disjoint).

## Reproducing the paper

```bash
pip install scikit-learn scipy numpy matplotlib

# ONE COMMAND — every number in the manuscript against its artifact.
# Chains the checks below; non-zero exit means a manuscript figure does not
# reproduce and submission must stop.
python experiment_code/verify_paper_numbers.py

# stage 1 — build the dataset (prints a verification gate: 13,360 rows,
# class counts must match the paper or the script aborts)
python experiment_code/preprocess_data.py

# stage 2 — all models, both protocols, ablation, collision analysis
python experiment_code/pipeline_authoritative.py all    # or: a | b | misc | llm

# pairwise McNemar matrix and per-class detail
python experiment_code/mcnemar_matrix.py

# audit: recompute the LLM numbers the JSON does not store
# (per-class recall/precision, prediction distributions, every McNemar row
#  involving an LLM) and print PASS/FAIL against the manuscript
python experiment_code/audit_llm_numbers.py

# alignment gate: every LLM prediction file must line up row-for-row with the
# authoritative test partition. The LLM files are written one record per call
# batch, so their file order is NOT the sample order — sort by `idx` first.
# A McNemar row computed on misaligned files still prints a plausible
# chi-square, which is why this runs before any table is quoted.
python experiment_code/verify_mcnemar_alignment.py

# mixed signature groups: entropy spectrum and signature-only ceiling (§4.3)
python experiment_code/equivalence_spectrum.py

# dataset descriptives: Table 1, its footnote, and the Figure 2 caption —
# per-verdict counts, mean execution times, TLE/MLE limit modes, submitter
# statistics, and the five difficulty-tier shares. Exit 0 = all reproduce.
python experiment_code/dataset_descriptives.py

# problem-difficulty tiers (§5.5): 92.21 / 93.60 / 87.55% with compositions
python experiment_code/difficulty_tier_analysis.py

# submitter-disjoint replication (§5.1): GroupShuffleSplit over user_handle,
# zero overlap, writes user_disjoint_results_v3.json
python experiment_code/user_disjoint_replication_v3.py

# clustering diagnostic (§5.1): per-class ICC of the verdict, design effect
# and effective sample size behind the "p-values are lower bounds" caveat.
# Writes clustering_diagnostic.json; exit 0 = the manuscript's figures match.
python experiment_code/clustering_diagnostic.py

# few-shot mechanism (§5): what the worked examples do, measured on the shared
# test partition — no-example run answers WA for 95.0% of submissions
# (CE recall 0.179), three-shot spreads to 62.6% (CE recall 1.000 at
# precision 0.321). Writes experiment_results/fewshot_mechanism.json.
python experiment_code/fewshot_mechanism_analysis.py

# learning curve (§4.4): accuracy vs training-set size, five repeats per
# size; the manuscript's 85.8 / 87.7 / 91.1 / 91.8% are the means. Writes
# experiment_results/learning_curve.json; exit 0 = the printed figures match.
python experiment_code/learning_curve.py

# ablation (Table 6 and the paragraph after it): the six leave-one-out
# removals, the earlier-only submitter aggregate, the whole-corpus variant
# that demonstrates the look-ahead artefact, and the submitter-disjoint null
# (the feature is constant on the test side there, so accuracy is unchanged).
# Writes experiment_results/ablation_study.json; exit 0 = all reproduce.
python experiment_code/ablation_study.py

# supervised tables and the claims that read them out: Table 2 (all cells),
# Table 3 (full confusion matrix + per-class F1), the Gini caption, the
# Section 4 narrative figures, and the Section 5.4 replication and corpus
# homogeneity numbers. Retrains Gradient Boosting for the prediction-level
# claims; exit 0 = every printed figure matches.
python experiment_code/verify_supervised_tables.py

# inference-latency benchmark (Table 7 footnote): per-1,000 latency for the
# three fitted models, single core, best of five; writes latency_benchmark.json
# with the host CPU. Latency is machine-dependent — read it as "measured on
# the authors' machine".
OMP_NUM_THREADS=1 python experiment_code/latency_benchmark.py

# bibliography audit: every DOI/arXiv id and every title, checked against the
# Crossref, DataCite, arXiv and OpenAlex registries. Exit code 0 = all clear.
python experiment_code/verify_references.py

python experiment_code/regenerate_figures_v3.py
```

## What is *not* reproducible from this repository

The two LLM result sets need live inference and are committed as JSON:

- `llm_experiments/*_fair_rerun_predictions.json` — the reported numbers
  (three-shot, eight submissions per call, temperature 0). Regenerating them
  needs a DeepSeek API key (`DEEPSEEK_API_KEY`) and Ollama for
  `qwen2.5:3b`.
- Everything else in `llm_experiments/` predates the current protocol and is
  superseded; see `deprecated_artifacts/README.md` for what those files are
  and why they are not citable.
- The 15-example dose-response arm (fixed batching, examples as the only
  varied factor) has not been run; it needs a DeepSeek API key. The two arms
  that *are* archived differ in call format as well as example count, which
  the manuscript states where their comparison is used.

**Credential hygiene.** No API key belongs in this repository. One was found
hardcoded in `run_deepseek_fewshot.py` on 2026-10-18 (invalid by then; the
commit that introduced it has been pushed to the public remote). It has been
replaced with a `DEEPSEEK_API_KEY` environment read. If you ever commit a
live key, rotate it at the provider — deleting the commit does not un-leak it.

Random seeds are fixed at 42 throughout. With scikit-learn 1.6.1 the output
reproduces the manuscript numbers exactly; other versions may differ in the
third decimal of the tree ensembles.

## Why `verify_references.py` exists

The bibliography went through a period in which several entries carried
plausible titles with DOIs that did not resolve, and one DOI that resolved to
an entirely different paper. Neither error is visible when reading a `.bib`
file. The script resolves every identifier and compares the registry's title
against the entry's, so a fabricated or mistyped reference fails loudly instead
of reaching a reviewer. It exits non-zero if anything needs attention, which
makes it usable as a pre-submission gate.

The script checks that each reference *exists*. It does not check that the
sentence citing it is true, and that turned out to be a separate problem of the
same size: after the metadata was clean, an audit of all 67 citation instances
against the source texts found ten more defects, including one paper credited
with four authors who are not on it, and a CS1 projection built on an error
distribution the cited paper never reports. If you re-use this bibliography,
treat both checks as required.

## The two evaluation protocols

- **Protocol A — stratified random 80/20.** The same partition used for the
  LLM runs, so every ML–LLM comparison is paired.
- **Protocol B — submitter-disjoint.** `GroupShuffleSplit` over
  `user_handle`, zero overlap (10,900 / 2,460). This is the cold-start
  setting that matters for deployment, and accuracy does not drop.
